# Arquitectura de ofertas y ecosistema

## Objetivo
Convertir dispersión de ideas, canales, productos y servicios en una arquitectura simple: qué enseña, qué transforma, qué acompaña, qué implementa y qué debe esperar.

Usar la plantilla `templates/mapa_maestro_v1.md` para el resultado principal.

## Cuándo usar
Aplicar cuando el usuario tenga varios de estos síntomas:
- Cada idea parece requerir una marca, dominio, red social o página propia.
- Los canales de distribución se confunden con productos o negocios.
- Hay contenido, guías, comunidad y servicios sin una escalera de valor clara.
- Un personaje o proyecto narrativo corre riesgo de independizarse antes de validar su función.
- Se pide rediseñar una web antes de saber qué ofertas, CTAs o rutas necesita.

## Principios no negociables
1. **Organizar por el trabajo que la persona necesita resolver**, no por plataforma, formato o personaje.
2. **Tratar Instagram, YouTube, podcast, blog y email como canales de distribución**, salvo decisión explícita y justificada de convertir uno en negocio.
3. **Exigir para todo activo:** casa, problema, promesa, entrada y salida.
4. **Enviar al Baúl de Ideas cualquier activo sin función o prioridad actual.**
5. **Congelar dominios, redes, páginas de producto y nuevos servicios** hasta que tengan una oferta definida y una razón operativa real.
6. **No rediseñar la web antes de validar el Mapa Maestro de Ofertas.**

## Flujo de trabajo

### 1. Reunir y sintetizar
Leer los documentos, notas, mapas, borradores y listados que aporte el usuario. Extraer nombres, productos, canales, audiencias, promesas, personajes, herramientas y servicios. No convertir todavía esa lista en una navegación web.

### 2. Definir la arquitectura madre
Elegir una arquitectura de intención. El patrón más útil es:

```text
APRENDER / ENTENDER  → contenido, educación, guía y sistema
HACER / RESOLVER     → diagnóstico e implementación profesional
```

Usar una marca madre solo si aporta orden. Si la marca madre es una rama operativa, señalar el riesgo de confusión y recomendar que el hub explique con claridad las dos puertas.

### 3. Clasificar activos
Crear entre cinco y siete casillas. Adaptar los nombres al usuario, pero conservar estas funciones:

| Casilla | Función |
| :--- | :--- |
| **Contenido / laboratorio** | Criterio, educación, atención y confianza |
| **Guía / low ticket** | Microtransformación o diagnóstico inicial |
| **Sistema / comunidad** | Método, práctica, herramientas y acompañamiento |
| **Implementación** | Servicio profesional para resolver o ejecutar |
| **Canales** | Distribución, no producto |
| **Herramientas internas** | Procesos, SOPs, prompts, tableros y operación |
| **Baúl de Ideas** | Iniciativas sin prioridad de ejecución |

### 4. Construir la escalera de valor
Definir un máximo inicial de cuatro niveles:

| Nivel | Trabajo | Pregunta de la persona |
| :---: | :--- | :--- |
| **0** | Contenido | *«¿Qué me está pasando?»* |
| **1** | Guía o activo inicial | *«¿Qué puedo resolver ahora?»* |
| **2** | Sistema o comunidad | *«¿Cómo lo hago con método y continuidad?»* |
| **3** | Implementación | *«¿Pueden hacerlo por mí?»* |

Para cada nivel, completar activo, problema, promesa, formato, entrada y salida. No inventar una oferta final si el usuario todavía no la definió; marcarla como pendiente.

### 5. Diseñar límites bloqueados
Crear una auditoría que diga qué **no se construye todavía** y por qué. Bloquear por defecto:
- Dominios, redes o webs separadas para personajes o verticales.
- Comunidades sin un activo inicial y señal de interés.
- Páginas de producto sin problema, promesa, formato, entrada y salida.
- Menús que prometan productos futuros.
- Servicios adicionales sin caso, proceso y mensaje claro.
- Rediseños web antes de que el mapa defina rutas y CTAs.

Definir para cada bloqueo una **condición de desbloqueo observable**.

### 6. Elegir el siguiente activo único
No recomendar una lista larga de iniciativas. Elegir un solo activo que haga real la arquitectura. Habitualmente será:
- Un Índice Maestro para una guía o producto inicial.
- Un primer activo diagnóstico con ejercicio y puerta de salida.
- Un mapa editorial que conecte contenido con una guía real.

Si el activo es una guía, construirla capítulo por capítulo:  
$$\text{Índice Maestro} \longrightarrow \text{congelar índice} \longrightarrow \text{Capítulo 1} \longrightarrow \text{historia} \longrightarrow \text{concepto} \longrightarrow \text{herramienta} \longrightarrow \text{ejemplo} \longrightarrow \text{ejercicio} \longrightarrow \text{decisión} \longrightarrow \text{test} \longrightarrow \text{salida.}$$  
*No escribir el libro entero de una vez.*

## Entregables mínimos
Preparar siempre:
1. **Mapa Maestro de Ofertas v1:** arquitectura, casillas y escalera de valor.
2. **Auditoría de bloqueos:** qué se congela, por qué y cómo se desbloquea.
3. **Siguiente paso único:** el próximo activo no visual antes de nuevas páginas o productos.

Usar tablas y diagramas ASCII simples. Si el usuario solicita presentación, crearla solo después de congelar el mapa y destacar los bloqueos en una diapositiva explícita.

## Criterio de calidad
El trabajo está listo si una nueva idea puede clasificarse en menos de un minuto y si la respuesta a *«¿qué hacemos ahora?»* es una sola acción concreta, no una lista de proyectos.
